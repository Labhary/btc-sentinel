# Private demo: fixed delivery plan

Authorization: private simulated deployment approved by the owner. Real trading,
live strategy dispatch, and public access to trading data remain excluded.

## Finish line

The owner can privately send /start, /help, /status, /pause, and /resume in Telegram;
see clearly labelled scripted simulation results; verify preference persistence
after a restart; and verify that other users receive no trading data.

This tests webhook authentication, owner access, D1 preferences, outbox delivery,
and results generated by the existing Python lifecycle simulators. It does not
exercise live collection, strategy admission, scheduled reports, or live trade
tracking. Those remain a separate observation stage.

## Deliverables and acceptance

1. Demo code and automated checks: isolated Worker entry, no cron, no state API,
   24 scripted closed trades generated using actual fixed/managed simulators.
2. Provisioning: dedicated Cloudflare Worker and D1 database, dedicated Telegram
   bot, owner ID and encrypted secrets. Never reuse a production bot/database.
3. Deployment: migrations, preview health check, owner webhook registration.
4. Owner acceptance: commands work, pause persists across redeployment, duplicate
   updates do not duplicate replies, outsiders/groups are ignored.

Only after step 4 is the private demo complete. No additional strategy tuning is
required to deliver this demo. Network/account access is required for steps 2–4.

## Operator setup

Copy worker/wrangler.demo.example.toml to worker/wrangler.demo.toml locally.
Create D1 database btc-sentinel-private-demo and set its returned ID in that file.
Use the project's installed Wrangler from worker/:

```sh
npx wrangler d1 create btc-sentinel-private-demo
npx wrangler d1 migrations apply btc-sentinel-private-demo --remote --config wrangler.demo.toml
npx wrangler secret put TELEGRAM_BOT_TOKEN --config wrangler.demo.toml
npx wrangler secret put TELEGRAM_ADMIN_USER_ID --config wrangler.demo.toml
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET --config wrangler.demo.toml
npx wrangler secret put STATE_API_HMAC_SECRET --config wrangler.demo.toml
npx wrangler deploy --config wrangler.demo.toml
```

Generate different random secrets of at least 32 characters for webhook and state
API. The latter is required by shared configuration but the demo exposes no state
API routes. Do not add GITHUB_ACTIONS_TOKEN. Register the dedicated bot webhook
using Telegram setWebhook with the deployed /telegram/webhook URL, matching
secret_token, and allowed_updates set to ["message"]. Do not place tokens in
repository files, chat, shell history or URLs printed to logs.

## Win-rate agreement

The owner requests an initial win-rate report after at least 20 closed observation
trades. Before 20, display sample progress only. At 20 or more, show strict win
rate, closed count, costs and uncertainty together; break-even closes stay in the
denominator and unresolved trades are excluded. Exactly 12/20 is 60%; exceeding
60% requires at least 13/20. This reporting threshold does not prove an edge or
replace the stronger historical validation requirements.

Scripted QA trades are never included in observation statistics. The demo's
12 wins and 12 losses are deliberately constructed, not measured market skill.
